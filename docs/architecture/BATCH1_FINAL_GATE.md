## Closure of the four rejection rounds

1. **Ownership and deadlocks:** Migrated-model writes and absence sweeps are excluded from the legacy mapper, with lock ordering and an intentional inversion mutation establishing deadlock sensitivity. Selected races and AIJob recovery have independent-instance tests. Tests 1–3 assert concurrent outcomes without deterministic barrier scheduling; no stronger proof is claimed.
2. **Foreign keys:** Both the empty target-ID-set case and the stale omitted-field case are fixed. `tests/business/batch1-multi-instance.spec.ts` test 8 confirms that a committed `journeyId` survives an omitted value, explicit null detaches, and a valid replacement changes the reference. The benchmark §60 rows 4 and 10 and multi-instance documentation no longer present the fixed omission defect as live. An historical account of the pre-fix defect is not a current defect assertion.
3. **Race-proof precision:** `StrictBarrier` rejects a missing party instead of silently releasing it. In test 5 the hooks establish overlap, **not same-row notification contention**: the worker reaches its hook before `createMany({ skipDuplicates: true })`, while mark-read holds the row lock. The test and §3.3 now explicitly disclaim lock-blocking proof. The underlying duplicate-delivery property is supported by the insert-on-conflict-no-op implementation, one-row/read-state assertions, and the reported clobbering-writer mutation failure.
4. **Measurement and provenance:** The benchmark separates AI-triggering Mode B's measured window from fully drained callbacks and limits constant-cost claims to sampled statement counts. Full-suite baseline comparison, typecheck/lint, and mutation outcomes are supplied results rather than reruns here; the two targeted specs above were independently rerun. The comparator only evaluates the report currently on disk, so its post-isolated-run success is not substituted for the supplied full-suite comparison.

## Scope and user-experience gate

The application remains **not multi-instance safe** while 35 models and FollowUpJob reads are process-local. Other disclosed limits include AIProvider historical-job deletion, AuditLog retention discontinuity, local-clock dependence of the five-minute AIJob recovery threshold, and D/E reviewer-model distinction. `DAPI_API_KEY` is empty, so live AI remains `AI_LIVE_BLOCKED_EXTERNAL`. No pet-presence acceptance session establishes that a user feels the pet is real; this persistence-only acceptance must not be represented as product-experience acceptance. None of these out-of-batch limitations independently rejects the eight-model persistence round.
