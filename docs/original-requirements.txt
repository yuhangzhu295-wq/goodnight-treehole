====================================================
三、核心原则，禁止违反
====================================================

1. 禁止只做 UI。
2. 禁止只做静态页面。
3. 禁止只做前台，不做后台。
4. 禁止只做后台，不做前台。
5. 禁止前台和后台各自写 mock 数据，假装联动。
6. 禁止前台直接调用第三方 AI API。
7. 禁止把 AI 模型写死成一家。
8. 禁止把 FAQ、回复预设、反馈分类写死在前端常量里。
9. 禁止把“树洞详情”和“回复抽屉打开态”拆成两个独立页面。
10. 禁止把用户隐私设置和系统默认设置混成一张表。
11. 禁止留下主链路 TODO。
12. 禁止没有测试就说完成。
13. 禁止视觉完全偏离参考图。
14. 禁止直接照搬 GPL 仓库代码；可借鉴结构，不可整仓复制。

前台和后台不得直接相互调用页面，也不得通过 localStorage 共享业务状态。
正确结构必须是：

用户前台 apps/mp
  -> 调用 /api/v1/*

管理员后台 apps/admin
  -> 调用 /api/admin/v1/*

统一业务后端 apps/api
  -> 共享同一套 Domain Services
  -> PostgreSQL / Redis / BullMQ / MinIO / LiteLLM

前台和后台必须共享同一套数据库、领域模型和服务层。
后台的审核、屏蔽、AI 路由、FAQ、回复预设、系统设置修改，必须真实影响前台展示和行为。

====================================================
十三、AI 架构
====================================================

禁止实现成开放聊天机器人。
本项目只做情绪辅助，不做心理诊断，不做医疗建议，不宣称治疗或治愈。

允许的 AI 能力：
- 树洞 5 风格温柔回应
- 今日回信
- 情绪拆解
- 月报总结
- 月报建议
- 月报海报文案
- 内容安全审核辅助

AI 架构：
- LiteLLM 作为统一 AI Gateway
- NestJS 后端实现 AI Router
- 前台永远只传业务意图和风格
- 前台永远不知道底层供应商
- 后台配置供应商、模型、路由、兜底和上限

AI Router 必须支持：
- 主模型
- 备用模型
- 模板兜底
- 失败重试
- 超时切换
- 供应商启停
- 风格级路由
- 任务日志
- 成本统计预留
- 失败原因记录
- trace 记录

AI 输出必须经过安全过滤。
AI 输出中不得出现：
- 医疗诊断
- 疾病判断
- “你一定会好”
- “我能治愈你”
- 鼓励自伤、自杀、暴力、攻击的话术

高风险内容处理：
- 检测自伤、自杀、暴力、极端攻击内容
- 前台显示温和提示
- 内容进入后台风险预警或待审核
- 不要让 AI 继续深聊危险内容
- 提示用户联系专业帮助或紧急热线

- 不允许授权失败后页面崩溃。

====================================================
十五、前后台联动验收
====================================================

必须实现并自动验证以下闭环：

1. 公开树洞审核闭环
用户前台发布公开树洞
-> 后端创建 Mood + Post
-> Post 进入 pending_review 或自动 published
-> 后台树洞内容列表出现该内容
-> 管理员审核通过
-> 前台广场刷新后可见

2. 回应审核闭环
用户前台发表回应
-> Reply 创建为 pending_review
-> 后台回应审核出现该回应
-> 管理员拦截
-> 前台树洞详情 replies 不再返回该回应

3. AI 路由闭环
管理员修改 warm 风格主模型
-> 用户重新生成今日回信
-> AIJob 使用新路由
-> 后台 AI 任务记录显示新 provider / model / routeVersion

4. 反馈工单闭环
用户前台提交反馈并上传截图
-> 后台反馈工单可见内容和图片
-> 管理员回复并标记已解决
-> 前台反馈状态可见变化

5. FAQ 联动闭环
管理员新增 FAQ
-> 前台帮助与反馈页刷新
-> 新 FAQ 可见

6. 回复预设联动闭环
管理员新增快捷回复
-> 前台树洞详情回复抽屉刷新
-> 新快捷回复可见

7. 系统隐私默认值闭环
管理员修改默认隐私策略
-> 新用户或新草稿默认值变化
-> 历史用户 PrivacySetting 不被覆盖

8. AI 失败兜底闭环
模拟主模型失败
-> 自动切备用模型
-> 备用也失败则模板兜底
-> 前台得到温和响应
-> 后台 AIJob 记录失败链路和兜底结果
