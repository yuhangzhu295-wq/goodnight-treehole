- **决策日期**：2026-10-29
- **适用范围**：`apps/mp`（C 端全部 39 个独立视图与共享组件）、`packages/ui-tokens`
- **关联审查**：`docs/design-v3/INDEPENDENT_UI_AUDIT.md`、`docs/design-v3/PAGE_REVIEW_MATRIX.json`

## 1. 决策背景与核心矛盾

在《晚安树洞》从 V1 向 V2/V3 演进及外部视觉审计过程中，暴露出三套视觉语言与两类产品哲学的碰撞：
1. **三套历史视觉语言的冲突**：
   - **语言 A（V2 主体系统）**：中性纯白底（`#FFFFFF`）、1px 细线分隔（`#E8EAED` / `#EBEDF0`）、深墨正文（`#242A32`）与克制深绿强调色（`#1E4D45` / `#275F56`）。
   - **语言 B（V1 遗留装饰系统）**：大面积深绿渐变 Hero 横幅、实时时钟装饰、每条树洞/每个情绪按钮重复出现的萌系树精灵卡通立绘、九宫格彩色插画卡。
   - **语言 C（独立海报系统）**：米黄色背景、植物底纹与情绪折线图的“月报海报”样式。
2. **通用社交媒体规范 vs 夜间心理安全庇护所定位的冲突**：
   - 外部审计试图以通用社交平台（如 Soul 广场、微博）的标准要求《晚安树洞》强化“社交识别度”、丰富卡片视觉刺激。
   - 然而，《晚安树洞》的核心用户处于夜间情绪脆弱、焦虑、失眠或关系受挫状态。高唤醒度、强人设识别与社交比较机制会直接破坏心理安全感并诱发二次焦虑。

本架构决策记录（ADR）正式确立：**全量统一采用“中性白底 + 细线分隔 + 克制深绿”系统（语言 A），彻底废除 V1 装饰立绘刷屏（语言 B）与米黄海报折线图（语言 C），并严格拒绝任何高刺激社媒化改造。**

## 2. 为什么坚持“中性白底 + 克制深绿”设计系统

### 2.1 低认知负荷与低生理唤醒（Low Cognitive Load & Low Arousal）
- 用户在深夜进入应用倾诉或寻求稳定支持时，工作记忆容量下降，对高饱和度色块、复杂多层嵌套卡片（Box-in-Box）和密集装饰极其敏感。
- 纯白底色（`#FFFFFF`）配合无圆角全宽细线分隔（`border-bottom: 1px solid #E8EAED; border-radius: 0`）使界面退后，让用户自己写下的文字、同行者的真实经历与最小可执行行动成为唯一视觉焦点（如 `Square.vue` 改造后墨量由 21.1% 降至 12.0%，高饱和像素下降 91%）。

### 2.2 统一跨模块阅读心智
- 无论是私密记录（`DiaryList`、`DiaryDetail`）、回信阅读（`LetterToday`、`LetterDetail`）、同行支持（`PeerNetwork`、`PeerConversation`）还是心理工具（`ToolIndex`、`ToolDecompose`、`ToolRun`），统一使用一致的顶栏高度（`52px–58px`）、一致的返回符号（`‹`）、一致的正文字号与行高（`16px / 1.85`），消除模块切换时的割裂感。

### 2.3 核心设计令牌（Design Tokens）强制规范
| 令牌语义 | 标准色值 / 规格 | 架构约束说明 |
|---|---|---|
| 页面背景 `--gn-bg` | `#FFFFFF` | C 端全部 39 页主背景统一为纯白，禁止单页私设米黄或深灰全屏底色 |
| 次级容器背景 `--gn-surface` | `#F7F8FA` | 仅用于输入框底色、轻量提示块或非激活胶囊 |
| 分隔细线 `--gn-divider` | `#E8EAED` / `#EBEDF0` | 列表项之间优先使用 `1px` 水平细线，禁止四边描边圆角卡片套卡片 |
| 主正文 `--gn-text` | `#242A32` | 标题与核心正文，保证高对比度易读性 |
| 次级说明 `--gn-subtext` | `#757D87` / `#7A838E` | 时间戳、来源说明、辅助提示 |
| 品牌主强调色 `--gn-primary` | `#1E4D45` / `#275F56` | 克制深森林绿，仅用于主 CTA 按钮、激活态 Tab 与选中芯片 |
| 浅绿辅助底色 `--gn-green-light` | `#EAF4EE` | 仅用于低谷预案/呼吸练习等温和状态提示图标底衬 |
| 危机警示色 `--gn-danger` | `#C93B3B` / `#FDF2F2` | **唯一高优特权色**，严格限定于 `SafetySupport` 立即危险区块与不可逆删除确认 |

## 3. 为什么拒绝高密度社媒化刺激（反微博 / 反 Soul 广场原则）

### 3.1 拒绝强化“社交识别度”与固定人设
- **决策**：驳回在 `PeerNetwork`（同路网络）和 `Square`（树洞广场）中增加个性化头像、固定作者代号、个人主页跳转或社交身份标签的建议。
- **理由**：
  1. **防跨帖拼图与熟人认出**：一旦在公共流中暴露稳定的 `authorCode` 或特殊头像，攻击者或熟人即可通过多条树洞的时间、地域与细节拼凑出真实身份，直接摧毁匿名树洞的立身之本。
  2. **去人设表演（Anti-Performative）**：没有个人主页与粉丝沉淀，用户才不需要为了“维持人设”或“博取关注”而修饰苦难，才能诚实面对自己的真实处境。

### 3.2 拒绝成瘾性交互与社交攀比指标
- **决策**：禁止无限下拉瀑布流、禁止多图九宫格视觉轰炸、禁止公开互动排行榜、禁止将“抱抱/回应”异化为竞争性热度指标。
- **理由**：
  1. 树洞的“抱抱”是单用户幂等的温和陪伴反馈，而非点赞竞赛。
  2. `PeerNetwork` 对雷同经历按标题聚合为单卡并标注“另有 N 位同行者留下过相同的经历”，是为了消除刷屏感并传递“你并不孤单”，而非制造热门话题榜单。

### 3.3 拒绝伪造情绪曲线与“治愈指数”
- **决策**：在 `ReportMonth`（月报）与 `Recovery`（生活恢复）中，严禁使用情绪高低折线图、打分制健康进度条或 AI 主观心理评语。
- **理由**：情绪波动不是绩效考核。低谷期的用户看到“本月情绪下滑 30%”或“打卡中断”只会加重自责。月报与生活恢复必须坚持**纯事实记录**（写了多少条记录、完成了哪几件具体小事、哪几天照顾了睡眠或饮食、自己留下过哪句原话）。

## 4. 吉祥物（树精灵）与海报风格的严格边界规范

### 4.1 吉祥物（Mascot / 树精灵立绘）使用边界
1. **全局禁用场景（零容忍）**：
   - 严禁在公共信息流（`Square`）的每条帖子中重复渲染吉祥物插画。
   - 严禁在表单输入页（`MoodCreate`、`FutureSelf`、`DecisionVault`）顶部放置巨幅吉祥物立绘挤压首屏输入区域与主 CTA。
   - 严禁在情绪选择器或功能导航（`ToolIndex`）中为每个选项配独立卡通形象（同屏不得出现多个吉祥物）。
   - 严禁在 `styles.scss` 中通过 `::before` / `::after` 伪元素（如旧版 `tree-top-cutout`、`tool-baby-letter-cutout`）全局注入装饰层。
2. **唯一允许场景**：
   - 仅允许在应用冷启动欢迎页、极少数无数据空态或特定温暖陪伴介绍节点以轻量、小尺寸、非干扰方式出现，且同屏最多不超过 1 处。

### 4.2 海报与信纸风格（Poster & Stationery）使用边界
1. **页面主体阅读**：
   - `LetterToday`、`LetterDetail`、`ReportMonth` 的主页面背景必须保持 `#FFFFFF` 纯白阅读版式，以字号层级、留白与落款传递信件与回顾的仪式感，禁止使用整页米黄色底纹或信封大图占据首屏。
2. **分享图弹窗（Share Modal）隔离**：
   - 海报样式（`makeShareImage` 生成的分享预览卡）仅在用户主动点击右上角 `⋯ → 分享图片` 触发 `shareOpen` 模态框时展示，与主页面阅读流严格隔离。

## 5. 组件级交互与工程质量硬性规范

为确保 UI 诚实度与架构稳定性，所有进入 `MINOR_REFINE` 的视图必须遵守以下四条工程准则：

1. **符号诚实准则（去伪导航箭头）**：
   - 右向尖括号 `›`（Chevron Right）**仅允许用于触发路由跳转或打开新视图的行级入口**（如“查看原始记录”“回到回信列表”）。
   - 原地执行状态切换或异步动作的按钮（如 `LetterToday.vue` 的“存入日记”行、`LetterDetail.vue` 的“收藏这封信”与“喜欢这封信”行）**严禁渲染右侧 `›` 箭头**，避免给用户造成“点击会跳转新页面”的虚假心理预期。
2. **领域语义对齐准则（收藏 vs 存入日记）**：
   - `Favorite`（收藏夹，对应 `/api/v1/favorites` 与 `/api/v1/letters/:id/favorite`）与 `Diary`（私密日记，对应 `/api/v1/letters/:id/save-to-diary`）是两个独立的持久化模型。
   - 按钮文案必须如实反映其调用的后端契约：调用 `save-to-diary` 时文案必须明确为“存入日记 / 已存入日记”（或同步接入真实收藏接口），严禁按钮写“收藏”而状态提示写“已保存到日记”。
3. **列表完整可达准则（禁止静默死截断）**：
   - 任何展示计数的列表（如 `PostDetail.vue` 显示 `回应（N）`），严禁在模板中写死 `replies.slice(0, 5)` 而不提供展开或分页入口。若首屏折叠展示前 5 条，当 `replies.length > 5` 时必须提供“展开全部 N 条回应”或分页加载控件。
4. **个人归档隔离与异步生命周期准则**：
   - 个人归档页（`Archive.vue`）的所有 Tab 必须严格限定为当前用户本人的数据，严禁将全站公共流混入个人档案。
   - 凡包含 `setInterval` 或循环 `setTimeout` 轮询 AI 任务（`waitForAiJob` / `waitForJob` / `waitForAnalysis`）的组件，必须在 `onBeforeUnmount` 中设置取消标志或递增 `runSeq` 并清理定时器，严禁组件卸载后继续后台轮询。
